# 設計歷程頁

狀態：已合併｜完成：新增「設計歷程」分頁：時間軸、兩版手繪與現行圖面並排、八個轉折、四個更正過的錯誤與待解問題，舊數值引自發布紀錄並由建置比對｜等誰：—

來自：[DEC-152](../decisions.md)、[DEC-180](../decisions.md)、[新增網站主題方案](https://claude.ai/artifact/TGHTXewPyKNWHZsdpxS6g4)〈各主題內容規劃〉的「設計歷程」

- 任務：TASK-140
- 核准：使用者 2026-11-22 在方案的決定卡選擇「四頁全做」，同日在第二張決定卡選擇把第一版、第二版手繪和現行圖面並排

## 目的

網站的四個敘事方向裡，「向時間」沒有佐證頁。repo 裡有 26 筆發布紀錄、一百多條決策與兩版手繪稿，記錄了這個設計怎麼改、為什麼改、哪裡算錯過，但讀者只看得到最後的結果。不做的話，讀者無法分辨哪些是深思過的決定、哪些還沒有答案，也看不到作者的手繪稿怎麼變成現在的圖面。

## 範圍

- 新增 view `design-process`，頁名「設計歷程」，網址 `?view=design-process`，登錄在四向專題群組（`group: 'topics'`，DEC-170），第二層頁籤排在日照研究之後。
- 文案放 `content/design-process.md`，分六節：開場、時間軸（9 站）、同一張圖三個版本（一樓俯視圖、縱向剖面圖）、改了什麼為什麼改（8 項）、我們更正過的錯誤（4 項）、還沒有答案的問題（5 類）。
- 手繪稿 `SRC-CONCEPT-001`、`003`、`010`、`011` 另做網頁用衍生檔，放 `web/src/views/design-process/assets/`，原始檔不動；衍生方式與雜湊登錄在[基地與來源](../site-and-sources.md)。
- `tools/build/build-content.mjs` 新增 `{{record:<版本或 sources>|<原文>}}`：已被取代的舊值不在模型裡，改引自發布紀錄或來源登錄，原文不存在時建置失敗。
- 外部連結另開視窗的處理移到 `web/src/shared/external-links.ts`，隱藏文字的樣式移到設計系統的 `.site-visually-hidden`，關於頁改用共用的這一份。
- `tools/build/build-copy.mjs` 納入設計歷程頁；網站文字快照 `content/website-copy.md` 由下一次發版重產（DEC-200）。

不在範圍：

- 首頁的「現場與手稿」維持原樣。是否移到本頁由整體導覽方案決定，本頁先連回首頁那一段，不重複放同樣的圖。
- 紀錄裡沒有的內容不補寫：場勘與最早手繪稿的日期、泳池改大的原因、作者當時的想法。作者提供後再加。

## 驗收

- `npm run lint`、`npm run build`、`npm run test:e2e`、`git diff --check` 通過。
- 單元測試：引文在紀錄裡找不到、紀錄沒提供、鍵名不認得都會擋下；設計歷程文案六節齊全、時間軸標題有日期與名稱、每張圖三個版本各一段、連結只指向站內分頁或本 repo、不含手寫的帶單位數字；改模型的屋頂坡度後頁面內容跟著變。
- 瀏覽器測試：六個分頁在五種寬度下主導覽與四向專題頁籤都不溢出、分頁標題用頁名；設計歷程頁五節與目錄一致、六張圖都載入且有替代文字、四張手繪標出來源編號並可開啟大圖、外部連結另開視窗、手機寬度下三版改為直排、深連結捲到該節、可點目標不小於 44 px。
- 桌機與手機截圖附在 PR。
