# 一堂游泳課頁

狀態：已合併｜完成：新增「一堂游泳課」分頁：由模型畫出的一樓平面動線圖、從入口到池邊的五站、水中教學平台、五個安全與照顧位置與待解問題，主導覽變成八項｜等誰：—

來自：[DEC-152](../decisions.md)、[DEC-157](../decisions.md)、[DEC-158](../decisions.md)、[DEC-182](../decisions.md)、[新增網站主題方案](https://claude.ai/artifact/TGHTXewPyKNWHZsdpxS6g4)〈各主題內容規劃〉的「一堂游泳課」

- 任務：TASK-142
- 核准：使用者 2026-11-22 在方案的決定卡選擇「四頁全做」

## 目的

網站的四個敘事方向裡，「向人」只談了玻璃牆與樓梯的視線，沒有說一班學生進來以後怎麼走。一樓已經照一堂課的順序重排（DEC-157、模型 0.10.0），但這個安排只出現在平面圖的小字和 3D 裡。不做的話，讀者看不出換鞋玄關、乾式廊道、梯底沖身區為什麼在那裡，也不知道無障礙、救生與急救的位置。

## 範圍

- 新增 view `swim-class`，頁名「一堂游泳課」（照 DEC-152、DEC-170 的稱呼），網址 `?view=swim-class`，登錄在四向專題群組（`group: 'topics'`），第二層頁籤排在水循環之後。
- 新增 `core/geometry/class-route.mjs`：從 active geometry 的 `l1.poolUse`、池體與 `ST-01` 整理出平面上的區塊、路線各站與由 bounds 算出的長寬；模型缺項就丟錯，不補值。建置時寫到 `web/src/generated/swim-class-data.json`。
- 文案放 `content/swim-class.md`，分五節：開場、從入口到池邊的五站、在水裡、看得見也照顧得到、還沒有答案的問題。人數、鞋櫃、階數、坡度、水深等都用模型 token。
- 頁面用同一份資料畫兩張簡化的一樓平面：一張標路線 1 到 5，一張標安全與照顧位置 A 到 E。滑鼠移到某一站、聚焦或按下它的按鈕，圖上對應的位置會標出來。手機上平面圖可以左右滑動，並且在清單捲動時留在頁首下方。
- 設計歷程頁「一樓照一堂游泳課重排」加上到本頁的連結。
- `tools/build/build-copy.mjs` 納入本頁；網站文字快照 `content/website-copy.md` 由下一次發版重產（DEC-200）。

不在範圍：

- 不新增設計內容。下課回程的細節、班級人數與課表不是模型裡的答案；頁面只寫「照同一條路往回走」，並把一班人數列為設計假設。
- 不另嵌 3D 畫面，連到 3D 頁的向人場景（`?view=3d-viewer#people`）；3D 裡的一堂課導覽由 3D 的任務處理。
- 二樓更衣淋浴區的平面不在本頁畫出，完整圖面連到圖面頁。
- 四個說明頁的頁內目錄、分節標題與卡片樣式各寫了一份，尚未抽成共用元件；留給樣式整理的任務一起處理。

## 驗收

- `npm run lint`、`npm run build`、`npm run test:e2e`、`git diff --check` 通過。
- 單元測試：路線各站照模型順序並對到平面上的位置；長寬等於模型 bounds 的差，坡道長等於高差乘坡度比，水道寬度相加等於池寬；模型缺項、尺寸為零、路線落在未知位置、平台超出池體都會擋下；文案五節齊全、站數等於模型路線、不含內部代號與手寫的帶單位數字；改模型的班級人數與平台水深後頁面跟著變。
- 瀏覽器測試：八個分頁在五種寬度下主導覽與四向專題頁籤都不溢出、分頁標題用頁名；兩張平面的模型版次和頁尾一致；標記都在圖內、路線標記落在自己的區塊裡、教學平台在池內；滑鼠、鍵盤與觸控都能選取，兩張圖互不影響；手機上點一站會把標記捲進圖框、平面留在頁首下方、頁面不會變寬；可點目標不小於 44 px。
- 桌機與手機截圖附在 PR。

- 新增 6 個單元測試與本頁的瀏覽器測試；原有測試只把分頁數由七改成八、四向專題的路由加上本頁，並在設計歷程頁的站內連結名單加上本頁，沒有刪除或放寬。
