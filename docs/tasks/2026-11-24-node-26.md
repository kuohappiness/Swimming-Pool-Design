# 建置與部署的 Node 由 22 升到 26

狀態：已合併｜完成：`.node-version`、`engines` 與 GitHub Pages 部署都改用 Node 26，`@types/node` 對齊 26，建置、單元與瀏覽器測試在 Node 26 全過｜等誰：—

- 日期：2026-11-24
- 類型：build
- 任務：TASK-185
- 核准：使用者 2026-11-24 在決定卡選「升到 Node 26」（選項：Node 24／Node 26／維持 Node 22）。協調者同日放行共用檔

來自：[程式碼品質改善方案](https://claude.ai/artifact/Fb7Kq1AZeRKA5i3Huofpot)〈實作順序〉階段 7（大版本升級）

## 目的

Node 22 在 2027 年 4 月停止維護；原本三處版本也不一致：PR 檢查讀 `.node-version`（22），部署寫死 `node-version: 22`，型別定義 `@types/node` 卻是 24。

## 範圍

- `.node-version`：22 → 26。PR 檢查（`ci.yml`）本來就讀這個檔，不用改。
- `.github/workflows/deploy-pages.yml`：改讀 `.node-version`，不再寫死版本；`actions/setup-node` 由 `@v6` 改成與 `ci.yml` 相同、釘住 commit 的 v7.1.0。
- `package.json`、`package-lock.json`：`engines.node` 由 `>=22.13` 改為 `>=26`；`@types/node` 由 `^24.19.2` 改為 `^26.6.6`（連帶 `undici-types` 8.9）。
- `docs/agents/workflow.md`：註明 Node 版本以 `.node-version` 為準。

不做：其他 Actions 的大版本（Dependabot #25 另處理）；本機開發環境的安裝。

## 注意

- Node 26 的 `node --test` 預設以 spec 格式輸出（`✔`、`ℹ tests 378`），不再是 TAP 的 `# tests`；只是畫面不同，結束代碼照舊。
- 本機 Node 比 26 舊時 `npm install` 會提示 `engines` 不符（只是警告）；要和 PR 檢查一致請裝 Node 26。

## 驗收

- 以 Node 26.13 重新 `npm ci` 後，`npm run lint`、`npm run build`（378 個單元測試）、`npm run test:e2e`、`git diff --check` 通過。
- PR 上的檢查以 Node 26 執行並通過。
