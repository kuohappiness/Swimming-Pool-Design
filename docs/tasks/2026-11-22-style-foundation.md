# 樣式打底：設計系統分層、分頁樣式不外溢

狀態：待審｜下一步：使用者審閱 PR 後合併｜等誰：使用者

- 任務：TASK-170
- 核准：使用者 2026-11-22 在決定卡選定視覺方向「保留現有風格並全面精修」（[DEC-210](../decisions.md)），同日另一張決定卡同意開工階段一

來自：[網頁樣式審查與改善方案](https://claude.ai/artifact/WTV9jhHer5b5eiMjk3GBDj)〈實作順序〉階段一

## 目的

審查時量到四個分頁各有一套樣式，而且互相覆蓋：圖面頁與日照頁各帶一支舊樣式檔，裡面直接改 `:root`、`html`、`body`、`h1`、`footer`、`svg`、`table`，所以同一個頁首與頁尾在不同分頁的字體、底色與對齊都不一樣（日照頁的頁尾比內容窄 20px），也讓任何人改共用樣式時無法預期結果。

這一步不改外觀，只把地基整理好：共用樣式有固定的先後，分頁樣式只影響自己那一頁，並由檢查擋住再犯。之後的可讀性、頁首頁尾、各頁版面才能一頁一頁改而不互相牽動。不做的話，後面每一階段都得先猜「這條規則會被哪一頁的哪支舊檔蓋掉」。

## 範圍

共用樣式（`web/src/design-system/`）：

- 新增 `index.css` 當唯一入口，在這裡定層的先後 `reset → tokens → base → layout → components`；後面的層蓋過前面的層，不看選擇器權重。`bootstrap.ts` 只匯入這一個檔。
- 新增 `reset.css`，收原本散在 `layout.css` 開頭與 `components.css` 結尾的基礎重設與「減少動態效果」規則。
- 分頁的 `view.css` 不放進層，所以一定蓋過共用樣式，不需要加重選擇器或 `!important`。
- 刪掉沒有任何畫面在用的規則（`.site-identity-copy small` 三處）與七個沒人用的設計變數。

分頁樣式：

- 圖面頁、日照頁：舊的 `styles.css` 併入 `view.css` 後刪除，一頁一檔。全部規則包在 `:where(.site-view--<view id>) { … }` 裡，`h1`、`h2`、`svg`、`table`、`button` 這類標籤選擇器只在這一頁的內容區生效；`:where()` 不增加選擇器權重，頁內原本的先後關係不變。
- 刪掉對不到任何元素的規則：圖面頁 183 個選擇器（舊版手繪圖面語彙，現在的圖面是 `drawings/current/` 的 SVG，自帶樣式）、日照頁 70 個（範本裡被 `index.ts` 拿掉的舊頁首、結論卡與設計重點）、設計理念頁 2 個。判定方式是實際開啟每一頁、每一張圖面並操作控制項後比對，再逐一對照範本與程式確認。
- 同一個選擇器前後寫兩次、後面蓋掉前面的宣告合併成一份（原本先寫深色主題，再被淺色覆蓋）。
- 分頁對頁尾間距的調整改寫成 `.site-view--<view id> + .site-footer`。

檢查：

- 新增 stylelint 外掛 `tools/check/stylelint-view-scope.mjs`（規則 `swimming-pool/view-scope`）：分頁樣式最外層的選擇器只能以這一頁自己的 class、id 或 `:where(.<class>)` 開頭，不能寫 `html`、`body`、標籤、屬性選擇器或 `.site-*`；包在 `@media` 裡的一樣檢查。另加 `max-nesting-depth: 1`，巢狀只用來限定分頁範圍。
- 單元測試 `tests/unit/web/design-system/tokens.test.mjs`：用到的 `--site-*` 都有定義、定義的都有人用、只在 `tokens.css` 定義。

不做（之後再做）：

- 3D 展示頁的 `styles.css` 與 `view.css` 一行未動，也暫不受 `view-scope` 檢查。3D 介面正在大改（TASK-150 至 152），協調者 2026-11-22 要求打底先不碰，等 3D 介面改版時併成一檔並納入檢查。
- 圖面頁與日照頁內容區沿用舊檔的字體（Inter 開頭的字體串）與寫死的色碼。統一字體、把色彩與字級改成設計變數是階段二。
- `drawings/current/*.svg` 內嵌的 `<style>` 用 `text`、`.title`、`.label`、`.grid` 這類通用名稱，內嵌到頁面後會影響同頁其他 SVG。圖面由 `build:drawings` 產生，class 加前綴要改產生程式，已與程式碼串約定由它處理。
- 視覺回歸測試（截圖基準）與 axe 無障礙檢查進 CI，屬程式碼串的測試工具階段。

與其他進行中工作的先後：

- PR #11（關於頁）改 `layout.css` 的導覽欄位並新增 `views/about/view.css`。兩邊改的行不重疊。它後合併時要把 main 合進去，`about/view.css` 最外層若有標籤或 `.site-*` 選擇器，`npm run lint:css` 會指出來。
- PR #19（3D 日照時刻）改 `3d-viewer/view.css`，本任務沒有動這個檔。

## 驗收

- 內容區外觀不變：改動前後各建置一份，用瀏覽器逐一比對每個元素實際套用的樣式（含 `::before`、`::after`），範圍是設計理念、日照研究、圖面五張、3D 共 8 個畫面，各 11 種寬度（1440 到 320，涵蓋全部斷點），另加列印與「不減少動態效果」兩種情況。
- 預期只有下列差異，其餘為零：
  1. 頁首與頁尾在四頁用同一套字體（原本圖面頁、日照頁被舊檔改成 Inter 開頭的字體串）。
  2. 日照頁頁尾與內容對齊（原本被舊檔限制在 1360px，比內容窄 20px）。
  3. 圖面頁、日照頁捲動超出頁面時露出的底色改為紙色（原本圖面頁是深藍 `#07131f`）。
  4. 圖面頁籤：滑鼠移入時文字變深，不再出現青色邊線；鍵盤焦點有赭紅外框（原本舊檔寫了 `outline: none`，鍵盤使用者看不到焦點）。
  5. 頁尾「單位 m」不再被轉成大寫「M」。
  6. 圖面頁列印時，舊檔的列印規則（隱藏頁籤與工具列、拿掉外框）原本被後面的規則蓋掉一半，現在完整生效。
- `npm run lint`、`npm run build`、`npm run test:e2e`、`git diff --check` 通過。
- 故意在分頁樣式寫 `body`、`h1`、`.site-footer`、`@media` 內的 `table`，`npm run lint:css` 都會擋下。

## 結果

2026-11-22，雲端環境（Chromium，SwiftShader）：

- 比對結果與上面六項一致，內容區（`main` 以內）在 88 個畫面與寬度組合下沒有任何元素的樣式改變；寬高也沒有改變。其餘出現在比對報告裡的只有不影響畫面的計算值：寬度為 0 的邊框顏色、`gap: 0` 與預設值 `normal`、頁尾的 `justify-content`。
- 3D 頁唯一的差異是「減少動態效果」時動畫時間由 0.001ms 變成 0.01ms（共用的重設規則現在優先於 3D 舊檔那一條），看不出差別。
- 樣式檔行數：圖面頁兩檔共 478 行減為一檔 327 行；日照頁兩檔共 969 行變成一檔 1,206 行，行數變多是因為舊檔一行寫一整條規則，併入後依 Prettier 展開成一行一個宣告，實際少了 70 個選擇器。
- 前後對照截圖在專案檔案區 `style-audit/stage-1/`：日照頁頁尾（電腦、手機）、圖面頁籤的鍵盤焦點與滑鼠移入。
- 順帶發現、不在本任務處理：圖面頁工具列的「工作值」勾選框沒有作用。它切換 `.hide-working`，對應的舊規則要隱藏 `.expansion`，但現在的圖面沒有這個 class（工作值用的是 `.working`）。規則已當成無效樣式刪除，勾選框該隱藏什麼需要決定，已轉告程式碼串。
