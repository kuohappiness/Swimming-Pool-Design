## 1. 執行原則

依 [0.9.0 統一公開成果展設計](2026-07-25-v0.9.0-unified-public-exhibition-design.md)依序實作 `TASK-075`～`TASK-082`。所有任務在同一整合工作線順序執行，同一時間最多一項 `in_progress`，不啟用 0.7.0／0.8.0 的平行工作例外。

每一階段先完成最小相稱驗證；最後由 `TASK-081` 做跨 view 完整回歸，`TASK-082` 才更新版本、契約與發布文件。

## 3. TASK-075｜不可變基線、單入口與路由骨架

### 工作

1. 建立 0.9.0 改版前的資料與視覺基線：
   - canonical model 設計子樹與 active geometry。
   - solar inputHash／analysis registry。
   - `viewer-model.json`／`concept-content.json` 的來源與同步狀態。
   - V067 current SVG／PNG 檔案 hash。
   - 三個現行入口的桌面 1440 × 900 與手機 390 × 844 截圖。
2. 把 Vite Rollup input 收斂為 `reference/index.html`。
3. 移除 `reference/solar-study/index.html` 與 `reference/3d-viewer/index.html`。
4. 建立 app root、query router、四個合法 route 及無效 route fallback。
5. 定義各 view 的 `mount(container)`／`destroy()` 邊界；先接入不改視覺的 adapter 骨架。
6. 讓 GitHub Pages workflow 只驗證單一正式入口。

### 驗證

- `dist/reference/index.html` 存在，舊兩個入口不存在。
- 四個 query route 均能直接載入，無效值回到設計理念。
- 3D bundle 未在非 3D view 首次載入。
- canonical geometry、solar inputHash 及 V067 圖檔 hash 無差異。
- `npm run check:docs`、`npm run typecheck`、focused router tests、production build、`git diff --check` 通過。

## 4. TASK-076｜共用設計系統、導覽與響應式殼層

### 工作

1. 建立 design token：顏色、字型角色、字級比例、行高、間距、線條、圓角、陰影與 motion。
2. 建立 App Shell、專案識別、四項中文主導覽、active／focus 狀態及頁尾聲明。
3. 桌面採穩定頂部導覽；手機採兩列 sticky header 與可水平滑動的文字導覽。
4. 建立共用文章、caption、數值、警語、按鈕、表單、panel 與 disclosure 樣式。
5. 移除共用層的漸層、發光、過度膠囊與普遍卡片陰影。
6. 遵守 reduced motion、safe area、44 px 觸控目標及 320 px 最低寬度。

### 驗證

- 四個 view 共用同一 header、字型與 token，不複製 header CSS。
- 320、390、768、1280、1440 px 無整頁水平溢出。
- 導覽可用鍵盤與觸控，active view 有非顏色單一辨識。
- 字型不存取外部 runtime origin。
- 視覺抽查確認風格優雅、舒服、克制，且沒有 SaaS／AI 儀表板式裝飾堆疊。

## 5. TASK-077｜設計理念策展頁

### 工作

1. 以 `docs/public/swimming-pool-renovation-design-concept.md` 及既有編譯 token 為唯一理念內容來源。
2. 建立作品首屏、核心引言及「向光、向水、向人、向時間」四個敘事章節。
3. `向水`包覆既有雨簾、收集、回用與建築水景內容，不改專業事實。
4. 調整圖文節奏、閱讀寬度、引言、章節編號及留白；不使用四張等權儀表板卡片。
5. 桌面可使用非對稱刊物構圖；手機改為連續單欄閱讀並保持自然章節節奏。

### 驗證

- active token 值與 0.8.2 基線一致。
- 公開理念正文沒有遺漏，非施工／專業限制仍可到達。
- 320／390 px 無孤行標題、文字過窄、裁切或水平溢出。
- 鍵盤與螢幕閱讀器能按章節順序閱讀。

## 6. TASK-078｜專業日照研究整合

### 工作

1. 在日照研究開頭加入「向光」的設計問題、策略與研究目的，但不取代專業摘要。
2. 將既有研究摘要、平面／剖面、控制器、讀值、代表時刻、方法與限制移入單一 view。
3. 以資訊層級區分設計引導、confirmed 工作值、即時比較值及專業限制。
4. 保留日期、時間、水平旋轉、外傾角、年份與手機 sticky 預覽的全部既有行為。
5. 將來源、完整方法與限制整理成可到達的專業區塊；不得隱藏 X33、23°外傾及工作 kWh 限制。

### 驗證

- v0.6.7、+25.5°、+23.0°、152.5°、+1,036.829 kWh 及 inputHash 狀態與基線一致。
- 既有 solar focused tests 全數通過且不重跑最佳化。
- 320／390／920 px 下控制器、sticky 預覽與完整 SVG 可用。
- 桌面與手機視覺檢查確認專業密度高但閱讀順序清楚。

## 7. TASK-079｜圖面設計整合

### 工作

1. 將現行 atlas 掛載為 `drawings` view。
2. 把視覺殼層改為建築圖冊：清楚圖面目錄、最大化圖面、克制工具列與詳情區。
3. 保留五個 current sheet、內嵌 SVG、ID 選取、縮放、符合畫面及 L3 太陽能板控制。
4. 桌面保留圖面與詳情並置；手機依序呈現目錄、圖面與可收合詳情。
5. 不修改或重新輸出 V067 SVG／PNG。

### 驗證

- sheet registry 仍恰為 `REF-001`、`V067-L1`、`V067-L2`、`V067-L3`、`V067-SECTION`。
- V067 SVG／PNG hash 與 TASK-075 基線一致。
- 圖框、比例、北向、版本與非施工圖聲明完整可見。
- 320／390 px 可操作、可查看完整圖框且不裁圖。

## 8. TASK-080｜3D 展示與實境漫遊整合

### 工作

1. 將現行 Viewer 改為可由 `3d-viewer` view 動態 mount／destroy 的 runtime。
2. 保留五場景、圖層、固定視角、泳池剖視、構件選取、資訊面板、品質階級與 diagnostics。
3. 重新整理控制器的視覺層級，使模型畫布優先，進階資訊漸進展開。
4. 保留 Inspect／第一人稱漫遊切換、七區 safe spawn、陸地／樓梯／游泳／水下及狀態恢復。
5. 手機控制改為不被共用導覽遮擋的可收合區與既有雙觸控面；safe area 與 44 px 控制不退步。
6. WebGL、enhanced necessary failure、optional asset failure 與 walkthrough unavailable 仍依既有契約降級。

### 驗證

- `viewer-model.json`／`concept-content.json` 同步、modelHash、active revision、SITE-XY 與 scene ID 契約通過。
- 進出 3D view 多次不累積 listener、RAF、WebGL canvas 或 overlay。
- desktop／390 × 844 E2E 覆蓋 Inspect、七區、樓梯、入水、水下、返回、退出與 snapshot restore。
- explicit baseline、necessary failure、optional degradation 與 static fallback 全部可用。
- 3D 幾何、碰撞、選取與移動測試無差異。

## 9. TASK-081｜跨 View、手機、無障礙與效能總驗收

### 工作

1. 依序切換四個 view，驗證 URL、active navigation、focus、scroll 及 runtime cleanup。
2. 檢查桌面 1440 × 900／1280 × 720、平板 768 px、手機 390 × 844／320 px。
3. 進行鍵盤、touch、ARIA、skip link、focus-visible、reduced motion 及對比檢查。
4. 比較 TASK-075 前後資料與視覺基線，確認差異只屬架構、版面與外觀。
5. 檢查初始 bundle；非 3D view 不預載 Three.js 重型 runtime。
6. 修正跨 view CSS 泄漏、scroll lock、重複 ID、overlay、listener 或資源殘留。

### 驗證

- `npm run check:docs`
- `npm run validate:reference`
- `npm test`
- `npm run typecheck`
- `npm run build`
- `npm run test:e2e`
- 桌面、平板、手機及 fallback 視覺檢查
- `git diff --check`

## 10. TASK-082｜0.9.0 契約、版本與發布

### 工作

1. 更新三份現行 output contract 為單入口及新的 query view。
2. 更新 README 的本機入口、公開成果及版本資訊。
3. 同步 package／網站／模型 release metadata 至 0.9.0；active geometry 維持 `GEO-0.8.2`，solar inputHash 不變。
4. 建立 `docs/releases/0.9.0.md`，記錄任務、驗證證據、不可變資料結果及已知限制。
5. 更新 GitHub Pages workflow 的單入口驗證。
6. 依使用者另行指示決定 commit／push；規劃本身不授權發布。

### 驗證

- 正式 artifact 只有單一主要 HTML 與其資產。
- 舊 `/solar-study/`、`/3d-viewer/` 不在 artifact 中且不建立轉址。
- 四個 query view 由公開 base path 可直接載入。
- canonical design data 只允許預期 release metadata 差異；active geometry、solar inputHash 與 current drawing hashes不變。
- 完整自動驗證、跨裝置視覺驗收及 `git diff --check` 通過。

## 11. 完成定義

只有在 `TASK-075`～`TASK-082` 皆達成驗收、規格轉為 `completed` 並封存、release 文件建立後，0.9.0 才可標記完成。頁面「看起來更好」不足以完成本版；單入口、資料不變、手機流暢、3D／日照功能完整及部署 artifact 正確同樣是發布門檻。
